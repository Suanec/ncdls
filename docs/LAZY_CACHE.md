# 按需缓存与每次进入的加载进度

版本：20261125.2。

## 之前为什么反复“下载”

旧版仅在点“保存离线资源”时注册缓存组件、把完整包保存到 Cache Storage。普通在线游玩只依靠浏览器 HTTP 临时缓存；本地开发服务器还明确设置了 `Cache-Control: no-store`。此外，启动器把从离线缓存读出的字节也统一显示成“正在下载”，容易误以为每次都重新传输。恢复入口解除旧离线组件后，旧资源虽然保留，也暂时没有组件负责读取它们。

## 现在的行为

- HTTPS 或 localhost 下，首页先显示进度，再准备按需缓存组件；只下载当前实际请求的文件。缓存准备失败或超时不会阻止联网游玩。
- 下载成功的资源经过长度和 SHA-256 校验后保存。同一版本再次进入先读取本机；不同版本按内容指纹复用未变化文件，包括中文名称的关卡资源。变更过的内容重新获取，失败响应和损坏文件不写入。
- 启动提示按实际来源显示“正在读取本机缓存”或“正在下载运行文件”，同时列出本机/网络读取量。即使完全没有网络资源传输，仍要执行脚本、创建引擎和构建关卡，所以进度界面仍会出现。
- “保存离线资源 / 检查并下载更新”仍是完整下载的唯一触发入口。只打开过的关卡不等于全部关卡已离线就绪；手动下载复用已经按需保存的文件。
- 已有完整旧离线版继续使用一致的旧版本，点击更新后才切换；遇到旧版锁住时可用 `recover.html`，保留存档和资源直接打开最新版。

按需缓存与存档分开。存档仍为 localStorage 的 `user_json_ncdls_web`，刷新后从当前关卡开头继续；此次未增加每一步棋盘快照。缓存只覆盖游戏目录，不处理其他站点或其他项目。

普通局域网 HTTP 不具备 Service Worker 条件，不能获得这一持久缓存能力。首次访问、新关卡缺少的资源、资源内容更新以及浏览器清理缓存后仍会下载。存储空间不足时缓存写入可能失败，联网游戏仍继续；浏览器也可能主动回收缓存。

## 下载、解包、初始化分别发生在什么时候

缓存内保存的是可直接读取的文件，不是每次进入再解包整套离线资源包。完整包只在手动下载时进行 JSON/Base64 解包并逐文件校验保存。构建阶段已解开原始 Brotli 资源。

每次打开仍需读取脚本、执行初始化、解析关卡与模型、解码图片并上传纹理，最后创建场景；这些工作会消耗 CPU/GPU，但不等于重新下载。页面分别显示“正在初始化游戏引擎”和“正在创建游戏场景”。引擎内部个别二进制/图片格式的解析仍发生在运行时，不应把这些处理统称为离线包解压。

缓存响应带有明确的来源标签；缓存缺少的文件才向站点发出请求并标为网络。无缓存组件时尝试用浏览器性能记录判断来源；浏览器未提供记录时会明确显示“来源待确认”，不把未知来源算作下载。

## 验证

Chrome 与 macOS WebKit 实际浏览器测试使用禁用 HTTP 缓存的静态测试服务器，首次启动未请求完整资源包或离线清单；第二次启动没有引擎、模型或图片资源网络请求，确认数据来自持久缓存。完整下载复用已经保存的引擎；Chrome 验证完整离线重新打开。另验证旧版升级、恢复入口保留存档及资源复用。报告位于 `reports/render-cache-*.json` 和 `reports/render-cache-upgrade.json`。

这次没有修改 9.3 MB 引擎文件的内容指纹；更新只需小文件和缓存组件。iOS 15 真机验证由用户复测，不能以 macOS WebKit 替代。
