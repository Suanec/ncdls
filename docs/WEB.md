# 网页版运行说明

此版本复用原 Laya、FairyGUI、Box2D 物理引擎、游戏 JavaScript、模型、音效和关卡数据，使用 HTML + CSS 包装页面。没有重新实现玩法，也不需要微信开发者工具。

## 启动

本机已有 Node.js。无需 `npm install`，在终端执行：

```sh
cd /Users/suanec/suanec/suanec-material/codes/ncdls
npm run web
```

浏览器访问 <http://127.0.0.1:8088/>。`npm run web` 会先构建，再启动仅监听本机的静态服务。按 Ctrl+C 停止服务。端口占用时可以使用：

```sh
PORT=8089 npm run serve:web
```

不要双击 HTML 以 `file://` 打开：游戏加载 JSON、WASM 和其他资源需要 HTTP。

鼠标点击或手指点车辆即可操作。页面右下角的「选择关卡」可以选择玩法和关卡；这会更新该玩法的进度。电脑上保持居中的竖屏游戏区，手机尺寸下自动适配。

## 手机上运行

手机和电脑连接同一 Wi-Fi。已经有 `web-game/` 时，在工程目录执行：

```sh
npm run serve:web:lan
```

首次构建或修改代码后，可用 `npm run web:lan` 一次完成构建与启动。

终端会输出 `LAN (en0): http://电脑局域网IP:8088/` 等地址，在手机的 Safari 或 Chrome 地址栏打开对应地址即可；不要在手机输入 `localhost` 或 `127.0.0.1`，它们指向手机自身。电脑需保持开机且服务持续运行。停止时按 Ctrl+C。

此命令监听局域网接口，让同网设备访问这个静态游戏目录。电脑原来的 `npm run web` / `npm run serve:web` 仍仅监听本机。也可以用 `NCDLS_HOST=电脑局域网IP npm run serve:web` 只监听指定接口。

打不开时，先确认手机没有使用蜂窝网络、IP 与端口正确，检查 macOS 防火墙是否允许 Node 的入站连接。如果公司或访客 Wi-Fi 开启了设备隔离，需要改用允许设备互访的网络，或将 `web-game/` 部署到手机能访问的内网站点。手机换 Wi-Fi 后电脑 IP 可能变化，以终端新输出为准。

手机与电脑的浏览器存档各自独立。已验证手机尺寸布局，尚未验证真实手机；若能打开页面但游戏异常，需要进一步检查对应手机浏览器的运行错误。

## 源码与产物

| 路径 | 用途 |
| --- | --- |
| `web/index.html`、`web/launcher.css`、`web/launcher.js` | 网页外壳、响应式布局、选关菜单 |
| `web/game.html`、`web/style.css`、`web/browser.js` | 游戏入口、模块加载与浏览器兼容 |
| `scripts/build-web.cjs` | 将原源码和资源生成网页版本 |
| `scripts/serve-web.cjs` | 无依赖的本地静态服务 |
| `scripts/check-web.cjs` | 产物哈希、语法、配置、WASM 与解压检查 |
| `web-game/` | 生成的可运行静态网页；可交给普通静态 HTTP 服务托管 |
| `web-game/web-build.json` | 构建文件清单与 SHA-256 |
| `reports/web-smoke-test.json` | 浏览器抽样验证记录 |

修改 `web/`、`src/`、`vendor/` 或同步资源后执行：

```sh
npm run build:web
npm run check:web
```

构建不会修改 `src/`、`vendor/`、`assets/`、`raw/` 和 `wechat-game/`。不要手动修改 `web-game/`；再次构建会拒绝覆盖已被手改的产物。

## 适配范围

1. 复用原模块加载顺序，跳过微信适配器、微信插件入口和分包启动入口，使用浏览器原生 DOM、Canvas、WebGL 与 WebAssembly。
2. 在构建阶段解压 885 个缓存中的 Brotli 资源，原始资源保持不变；为物理引擎补齐浏览器请求的 WASM 路径。
3. 在网页副本启动时改成本地资源根路径，关闭微信分包压缩加载与云存档配置。没有为网页新增后端。
4. 保留 Laya 自带的 `Texture.create`，阻止共享框架的另一套 WASM 快速路径覆盖它。测试中快速路径把 50×59 图集裁片裁成 5×11，造成按钮和螺丝板只显示碎片；原生实现显示正常。
5. 网页产物保留控制台日志，并注入选关桥接接口，调用原有模式、缓存和 `ToGame()` 流程。车辆阻挡、收集配色、物理掉落、胜负判断、关卡生成方式保持原实现。原先七个车位全部开放的修改继续生效。

进度使用浏览器 localStorage，键名为 `user_json_ncdls_web`，与旧 `carcrewd` 存档分开。同一主机与端口下刷新可保留进度；不同端口、不同浏览器、清理站点数据会使用不同或新的存档。保存的是关卡进度，不是关卡中途每辆车的位置。主题模式的计数也保留，但刷新后仍走原游戏的默认入口，可重新选主题关卡。

原 SDK 的浏览器分支仍保留；未接入真实微信登录、支付、广告、分享、排行榜或云服务。微信专属功能不属于本次运行验收。抽样测试中游戏资源请求均为本地同源地址；这不代表已审计并移除所有未触发的联网代码。

## 关卡与资源

选关菜单开放 5 种已有主资源的玩法，共 393 套关卡模板：经典 294、星星 12、海洋 27、冰雪 30、哪吒 30。地图、配色、难度读取原始配置；没有另造简化关卡。 从 `20261125.4` 起输入关卡号不受模板数量限制，按 `(关卡号 - 1) % 模板数 + 1` 选择模板，显示与存档保留输入关卡号。磁铁、刷新固定 1 次且不消耗，跳过这两个道具的广告分支。见 [具体规则与验证](UNLIMITED_PLAY.md)。

猫咪 12 条和打巨龙 110 条配置仍在原资源中，但 `dls_cat`、`other` 资源尚未缓存，因此选关菜单没有开放这两项。房间 2–12 的资源也仍然缺失，原游戏房间功能不在本次验证范围。

393 是可选配置数量，不是逐关通关测试数量，也不代表每个随机局面都有必胜证明。
