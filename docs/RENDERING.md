# 网页渲染兼容与重启说明

日期：2026-11-24；网页可见版本：`20261124.1`。

## 现象与排查结果

用户报告第一关车辆缺失、重叠或错位，第 100 关也只显示部分车辆；iPhone 13 Pro Max / iOS 15 的 Safari 和微信内置网页均有问题，从本地电脑提供的站点访问也会发生。用户还报告电脑打开 GitHub Pages 地址异常，因此不能只按 iOS 专属问题处理。

直接访问线上站点曾观察到第一关少黄色车辆、车位只显示右侧三个。线上离线清单与本地构建逐项比对，除 Node 版本造成的三个图标 PNG 压缩差异外一致；模型、场景、材质的文件引用不存在缺失和大小写不匹配。单靠这些静态检查不能证明 GPU 绘制正确。

## 本次改动

1. 在 `web/browser.js` 的 `NCDLSWeb.start` 中、`new W.M2` 创建绘图环境之前设置 `Laya.Config.useWebGL2 = false`。统一使用原引擎已有的 WebGL 1 路径，作为当前浏览器兼容方案。未升级引擎或改动模型、关卡、车辆坐标。曾尝试的全局关闭静态/动态批量绘制方案没有足够证据，已撤掉。
2. “选择关卡”菜单加入“重启游戏（保留存档）”。重启会先保存进度，再卸载旧游戏 iframe，重新创建引擎，恢复当前玩法及关卡。当前盘面的车辆移动不作为完整快照保存。
3. 捕获 `webglcontextlost`，显示明确的重启按钮；不让玩家面对无提示的残缺画面。错误后也可从选关菜单重启。
4. 页面显示版本号，并为本次变更的入口脚本和样式加版本参数，减少 HTTP 缓存继续使用旧入口的问题。离线 Service Worker 仍需通过更新按钮升级，网址参数不会绕过旧离线缓存。

Laya 引擎维护者针对 2.13 和 iOS 15 的花屏问题建议关闭 WebGL 2，见 [Laya 官方社区记录](https://ask.layabox.com/d/50469)；[WebKit Safari 15 说明](https://webkit.org/blog/11989/new-webkit-features-in-safari-15/)记录了 WebGL 2 与 Metal 渲染后端的引入。它们为回退方案提供依据，但不等于已经证明本工程全部设备上的具体底层根因。

## 检查与验收边界

- 自动检查覆盖 WebGL 1 设置早于引擎初始化、绘图环境中断提示、经典第 100 关重启、哪吒玩法重启恢复、初始化失败后重启，以及非当前 iframe 消息不能触发重启。
- `npm run check:web` 和 `npm run check:mobile` 检查构建哈希、脚本语法、关卡配置和离线资源完整性。
- 此版本尚未完成 iOS 15 真机视觉验收，不能表述为已彻底解决所有车辆漏画。最后验证期间浏览器控制接口不可用，没有用静态检查冒充画面测试。
- 需要在实际出错设备复测：经典第 1 关应显示完整车辆和车位；进入第 100 关检查完整布局；点重启后确认仍为第 100 关；切后台后再回来观察画面。WebGL 1 的性能与 WebGL 2 可能不同，密集关卡也需要留意流畅度。

## 如何获得新版

打开游戏后，在“选择关卡”菜单确认版本为 `20261124.1`。普通在线页面可使用 `https://suanec.github.io/ncdls/?v=20261124.1` 重新进入。已经保存离线包的设备，使用“离线与存档 → 检查并下载更新 → 应用更新并重启游戏”。

清理缓存、保留存档和彻底删除网站数据的区别见 [手机操作文档](MOBILE_OPERATION.md#清除缓存与存档的区别)。不需要重启 GitHub Pages 服务，也不需要清空存档才能应用修复。
