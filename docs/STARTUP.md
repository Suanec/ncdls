# 先显示页面，再加载游戏

版本：`20261124.5`。固定入口：[https://suanec.github.io/ncdls/](https://suanec.github.io/ncdls/)。

## 手机看到的过程

1. 首页 HTML 到达后先显示“正在准备游戏”和进度条。这个界面、基本样式及等待计时器均内嵌在 HTML，不依赖游戏引擎、图片或外部脚本。
2. 页面显示后才加载页面组件和游戏 iframe。下载运行文件时，显示已收到的 MB、总量和当前阶段百分比。
3. 进入本关资源加载阶段，显示已完成资源数和数据量。这个阶段无法预先得到准确总数，因此显示活动进度条，不伪造总百分比。
4. 初始化完成后进入游戏。遇到 HTTP 错误或运行文件不完整，会显示错误；点“重新加载（保留存档）”可重试。

等待时显示已用秒数。超过 12 秒没有新进展，会明确提示继续等待、检查网络或重新加载。运行文件下载如果 60 秒没有收到任何数据，会中止并显示重试提示；持续有数据的慢连接可以继续。

默认仍按需加载当前关卡。21 个资源包的完整下载仍由“离线与存档”里的手动按钮触发，见 [下载速度说明](DOWNLOAD_PERFORMANCE.md)。

## 如何获得新版

普通在线页面刷新固定入口即可。已经保存过离线包的设备，点“离线与存档 → 检查并下载更新 → 应用更新并重启游戏”，再在选关菜单确认 `20261124.5`。原有资源会按哈希复用，不需要清除网站数据或存档。

## 实现与验证

- `web/startup.css` 和 `web/startup.js` 构建时内嵌到首页；iframe 起初只有 `data-src`。可用时等首次内容绘制事件，再经过两次动画帧和一次任务让出；不支持绘制计时的浏览器使用后者作为兼容路径。之后才赋值外部资源地址。
- `scripts.json` 同时记录运行文件顺序与解压后的字节数。`web/browser.js` 用流式读取更新真实字节进度，下载完成后按原顺序执行 Blob 脚本，不先下载一遍又通过 script URL 重复下载。
- 加载反馈位于父页面，游戏 iframe 尚未初始化时仍然可见。消息校验来源和 iframe 身份；重试重新创建 iframe 并沿用存档。
- 本地 Chrome 慢网验证：首屏在 116 ms 绘制，后续页面资源从约 141 ms 才开始请求；人为延迟页面脚本及中断运行文件传输 13 秒，进度页保持可见，无新字节时百分比不增长。HTTP 503 后重试成功，第一关显示 4 辆车、7 个车位。

报告见 [首屏与慢网测试](../reports/startup-verification.json)。这些时间是本地控制实验，不是 iPhone 或 GitHub 网络速度承诺。iOS 15 真机未验收；历史上独立的画面停留问题不因加入进度条就被视为已修复。
