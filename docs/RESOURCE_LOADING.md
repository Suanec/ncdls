# 20261125.5：首次资源选择、自动修复与加载提示

本版只调整网页适配、缓存组件与提示，核心运行包内容哈希与 `.4` 相同；已有的约 9 MB 核心包可继续复用。

正式入口保持 [https://suanec.github.io/ncdls/](https://suanec.github.io/ncdls/)。从旧的完整离线版升级仍可使用“检查并下载更新”，或 [保留存档的恢复入口](https://suanec.github.io/ncdls/recover.html)。

## 9 MB 下载完，为什么还在加载？

约 9 MB 的核心运行包是引擎与游戏代码，不是全部游戏数据。之后还需要读取当前关卡的模型、图片、UI、物理文件等，再解析它们、创建车辆和螺丝。全部资源约 44.4 MiB（页面按约 45 MB 提示）。此前“网络下载 77 项”表示后续资源统计，不能认为代码文件下载完就可以跳过资源加载。

新提示区分：核心运行文件下载、本机缓存读取、资源下载（完成/待完成数量、当前文件与接收量）、解析资源与创建场景。不会把有请求尚未结束的阶段一律标成“正在解析”。

## 首次选择

手机离线版 `web_mobile/dist`（包括电脑访问正式站点）在启动游戏 iframe 前检查当前游戏目录自己的缓存：

- 仅有 HTML、CSS 等页面文件不算有游戏资源，会显示选择弹窗。
- **按需加载，先开始玩**：下载核心运行文件和当前需要的资源；后续关卡、道具资源首次使用时再下载并保存。
- **一次下载全部资源**：使用现有资源包下载和校验机制；等待全部保存完成后才启动游戏，不在引擎启动后争抢带宽。
- 已有运行文件或模型缓存时不再询问；未下载的内容继续按需补齐。
- 全部下载失败时保留已经保存的部分，可以重试，也可以选择按需加载。
- CacheStorage 不可用或普通局域网 HTTP 不支持 Service Worker 时，仍可在线按需游玩，不宣称已保存完整离线资源。

首次下载复用已经准备好的缓存组件，避免重复检查组件更新。下载中断监控从真正发出下载任务后开始，不能将准备阶段误判成中断。

## 自动补下载和版本提示

Service Worker 对构建清单声明的游戏资源按长度和 SHA-256 校验。网络返回的模型/图片等在校验通过前不会交给引擎解析，避免把半截文件当作正常模型继续初始化。

正常首次缺少缓存显示“正在下载资源”。发现已缓存版本不匹配、网络下载损坏或下载失败重试时，显示用户指定的 **“资源版本不匹配，正在更新”**，自动重新请求当前所需文件；不会因单个文件失败自动下载全部关卡。并发请求同一资源共享一次下载。

每个文件最多自动尝试 3 次，流式传输采用无新数据超时。持续断网、服务器文件一直缺失或持续返回无法校验的内容时，不能谎称还在更新：显示“资源更新暂未完成”，提供保留存档的重新加载操作。坏文件不会写入缓存。旧的完整离线包按自己的清单保持版本一致，避免混用旧引擎和新资源。

网页通用运行错误仍保留在诊断和控制台；玩家加载页不直接显示 `null is not an object` 等内部异常，也不会把所有未知逻辑错误伪装成正在下载。

## 截图中的空引用

`this._displayObject.size` 对应 FairyGUI 对象的尺寸更新。该框架在 `dispose()` 后将 `_displayObject` 置为 `null`，迟到的尺寸/布局回调如果继续访问它，会产生截图这一类异常。这与“网络资源不存在”不是同一个可直接等同的条件，仅凭截图不能确认具体回调来源。

网页版现在对已销毁对象的 `setSize`/`handleSizeChanged` 忽略后续调用，正常对象的布局逻辑保持原样；加载界面的 `onEvtProgress` 也先检查生命周期。资源下载失败和解析前校验则另行处理，不能只靠隐藏错误文本。

## 代码与验证

- `web_mobile/src/load-choice.js`：首次选择及等待完整下载。
- `web_mobile/src/mobile.js`：复用下载入口、显示完整下载进度、准备阶段与下载监控。
- `web_mobile/src/sw.js`：资源校验、合并并发请求、重试和状态通知。
- `web/browser.js`、`web/startup.js`：页面阶段展示、玩家错误信息、界面生命周期保护。
- `scripts/check-load-choice.cjs`：无资源/已有缓存、两种选择、下载完成前不进入、失败后可继续。
- `scripts/check-mobile-download.cjs`：缺失/损坏资源重试、旧缓存版本修复、合并请求、错误资源不入缓存、重试上限及既有离线回归。
- `scripts/check-browser-compat.cjs`、`scripts/check-startup-shell.cjs`：已销毁界面保护、首次选择阻止提前启动。

浏览器实测使用真正的 Service Worker 和缓存，服务端故意返回一次不完整图片，检查自动补下载、指定文案、正常进入游戏、重开复用缓存；另外测试首次完整下载后进入游戏。报告见 `reports/resource-loading-*.json`，浏览器脚本见 `scripts/probe-resource-loading.cjs`。桌面 Chrome / WebKit 测试不等于 iPhone 真机验证。
